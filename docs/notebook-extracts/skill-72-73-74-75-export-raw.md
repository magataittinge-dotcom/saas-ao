## #72 — Structure du ZIP (N5 + pratiques BE, réutilise #63/#67)
<!-- Skill technique : structure dérivée des captures N5 (#63 nommage/poids, #67 dépôt). -->
- ZIP avec **sous-dossiers par nature** : `Candidature/` (DC1, DC2, attestations) + `Offre_Lot_X/` (AE, DPGF/BPU, mémoire technique) ; un dossier par lot si multi-lots.
- Noms sans espaces/accents (cf. #66) ; chemin total ≤ 150 caractères.
- Une **checklist** (cf. #74) peut être placée en racine.
- Compatibilité PLACE (≤ 1 Go/fichier) / AWS (~30 Mo conseillé) ; macros/exécutables exclus.

## #73 — Page de garde (N3, 43615791)
- Éléments : **nom exact du lot et du MOA**, intitulé de l'AO, référence de consultation, date.
- **Logos de réassurance dès la page de garde** : macarons certifications (Qualibat, RGE, ISO) = signal de fiabilité immédiat (modèle SERI).
- **Charte graphique cohérente** (couleurs de l'entreprise dans titres/encadrés) ; éventuellement une belle photo de réalisation. Une mise en page bâclée = impression de négligence.
- **Chaînage avec un sommaire paginé** dès la page suivante. Ne pas ressembler à un Cerfa.

## #74 — Checklist de dépôt (N5 + pratiques BE, réutilise #67)
<!-- Skill technique : dérivée des procédures de dépôt N5 (#67). -->
- Étapes juste avant « envoyer » : bon **lot** sélectionné ; bons **fichiers** (pas de version obsolète) ; **signature** présente (par fichier, pas le ZIP) ; **nommage** conforme ; **poids/format** OK ; **avant l'heure limite** ; conserver **attestation/accusé de dépôt**.
- Pièges fréquents : mauvais lot, mauvais fichier, signature manquante.
